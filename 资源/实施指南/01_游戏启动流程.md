# 01_游戏启动流程

## 目标
从编辑器/运行包启动到主界面，再进入战斗流程；保证流程注册、UI 根节点、服务初始化正确。

## 必要组件与路径
- 场景：`Assets/_Game/Scenes/GameScene`（包含 CYFramework 根：UIRoot、[ObjectPools]、[Managers] 等）。
- 流程：`BootstrapProcedure` → `MenuProcedure` → `BattleProcedure` → `ResultProcedure`。
- 注册表：`Assets/CYFramework/Resources/CYFramework/ProcedureRegistry.asset`（改流程后用菜单生成）。

## 实施步骤
1) 场景检查  
   - 打开 `GameScene`，确认存在 `CYFramework` 预制结构；若缺失，从菜单 `CYFramework/创建框架预制体/全部创建` 生成，再保存场景。  
   - 确认 `UICamera` 绑定 Canvas，`[ObjectPools]` 存在且隐藏。
2) 流程实现  
   - 新建/补全流程脚本：`Assets/_Game/Scripts/Procedure/BootstrapProcedure.cs` 等，使用 `[AutoRegisterProcedure("Name")]`。  
   - 在 `BootstrapProcedure.OnEnter` 加载配置（ResourceLoader、UI 配置、数据预加载），然后 `CY.Procedure.Change("MenuProcedure")`。  
   - `MenuProcedure` 打开主界面 UI；开始按钮切到 `BattleProcedure`。  
   - `BattleProcedure` 启动战斗（见 04/05/06）；`ResultProcedure` 处理结算并返回菜单或重开。
3) 生成注册表  
   - 菜单执行 `CYFramework/Generate Procedure Registry`，生成/更新 `ProcedureRegistry.asset`。  
   - WebGL/微信必须使用注册表，不能依赖自动扫描。
4) UI 启动链路  
   - 主界面 Prefab 路径通过 `[UIPrefab("UI/Menu/Main/MainUI")]` 等指定；`CY.UI.Open<MainUI>()` 打开。  
   - 确认 UIManager 配置的 UIPanel 路径前缀与资源一致。
5) 数据预加载（可选）  
   - 如需提前加载 ScriptableObject（单位/指令/事件/波次），在 Bootstrap 中用 `CY.Resource.Load<T>()` 并缓存。  
   - 避免在首帧进行大量 IO，可用 `CY.Timer.NextFrame` 分帧加载。

## 自测清单
- 进入 Play：无缺失组件/注册表错误；主界面正常显示；按钮能进入战斗流程。  
- 流程切换：从菜单到战斗，再到结算，能够返回菜单；无重复注册或空引用。  
- UI 根：UI 关闭后回收到 `[ObjectPools]/UI`，层级顺序不乱。  
- 平台：在 WebGL/微信目标下打包，确认注册表生效、场景资源路径正确。
