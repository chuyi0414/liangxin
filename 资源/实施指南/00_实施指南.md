# 《良心防线》实施指南（详细版）

> 信息来源：`资源/策划` 全部文档（核心策划案、友/敌方单位库、词条库、扩展库、美术风格指南等）  
> 技术基线：`Assets/CYFramework`（流程/事件/UI/实体/资源/计时器/存档）  
> 已完成功能基线：`Assets/_Game`（现有主菜单/加载界面、场景/脚本等）  
> 目标：给“能直接做”的开发步骤与落地细节，避免遗漏；遇到“我很笨”时可当逐步操作手册。

---

## 1. 目标与交付闭环
- 必须跑通的最小循环：启动 → 主界面 → 进入战斗 → 一波战斗 → 结算/返回。
- 核心体验：寰瓥塔防 + Roguelike，Boss（玩家角色）招募/指挥“员工”战斗，资源收支与随机事件。
- 交付顺序：先有可玩闭环，再加深度（指挥/职业/部门/随机事件/Meta）。

## 2. 工程分层与路径
- 业务代码：`Assets/_Game/Scripts/*` 按模块分文件夹，避免“上帝类”；MonoBehaviour 挂载或 ScriptableObject 配置。
- 资源：`Assets/_Game/Art`、`Prefabs`、`ScriptableObjects`、`Resources`、`Scenes`。
- 框架：`Assets/CYFramework/*`，统一入口与 API：
  - 事件：`CY.Event.Post(ref evt)`，事件 `struct`，订阅 `void OnX(ref T evt)`，生命周期末尾 `UnsubscribeAll(this)`。
  - 流程：`CY.Procedure.Start/Change/ChangeProcedure<T>()`，流程类 `[AutoRegisterProcedure("Name")]`，改动后执行菜单 `CYFramework/Generate Procedure Registry`。
  - UI：`CY.UI.Open<T>() / Close<T>() / Back()`；高频 HUD 用 Typed MVVM（`ObservableProperty` + `TypedMVVMPanel<TViewModel>`）。
  - 实体：`CY.Entity.RegisterEntity/ShowEntity<T>/HideEntity/PauseEntity`。
  - 计时器：`CY.Timer.Delay/Loop/NextFrame`。
  - 存档：`CY.SaveData<T>() / CY.LoadData<T>() / CY.HasSave() / CY.DeleteSave()`。
  - 资源加载：`CY.Resource` 与配置的 ResourceLoader。
  - 对象池：UI 关闭回收到 `[ObjectPools]/UI`，并恢复 sibling index，复用不改变层级顺序。

## 3. 里程碑与验收清单
- M0 启动闭环  
  - 能进入主界面，按钮进入战斗流程；UI 关闭不残留；加载必要配置。  
  - 验收：`GameScene` 运行，`MenuProcedure`→`BattleProcedure` 切换无异常。
- M1 核心战斗  
  - 生成员工/敌人，基础 AI（移动/攻击），Boss 指令 F/A/D/S/R/G 生效；资源掉落/拾取；自闭/复活状态。  
  - 验收：一波战斗可打完，资源数值正确变化，指令行为符合策划。
- M2 进阶系统  
  - 职业/部门成长、Lieutenant（副官）指令、波次配置（含流量刺）、随机事件骨架。  
  - 验收：可加载多波次配置，指令/部门 Buff 生效，随机事件可触发并结算。
- M3 Roguelike & Meta  
  - 事件库数据驱动；办公用品/遗物；Meta 装修升级（Reputation），存档持久化。  
  - 验收：事件与奖励/代价一致；装修升级持久，重新进入游戏仍生效。
- M4 打磨  
  - UI/音效/动效接入，美术替换，性能与平台（WebGL/微信）适配，Bug 收敛。

## 4. 流程与场景
- 场景：保留 `GameScene`（包含 `CYFramework` 根、UIRoot 等），流程切换驱动状态，不频繁切换场景。
- 流程节点建议：
  - `BootstrapProcedure`：加载配置、预载资源、进入主菜单。
  - `MenuProcedure`：主界面（已有），处理开始游戏/设置/退出。
  - `BattleProcedure`：战斗逻辑，管理波次、指挥、单位生成/回收。
  - `ResultProcedure`：结算/重新开始/返回菜单。
- 每次新增/修改流程：执行菜单 `CYFramework/Generate Procedure Registry` 生成 `Assets/CYFramework/Resources/CYFramework/ProcedureRegistry.asset`，确保 WebGL/微信可用。

## 5. 数据与配置映射（ScriptableObject）
- 单位定义 `UnitDefinition`（新建 SO）：职业、基础属性（HP/攻击/移速/攻速/射程/AI 等级）、特殊被动、资源掉落、模型/Prefab。
- 部门定义 `DepartmentDefinition`：部门枚举、部门 Buff（加成、阈值）、权重。
- 指令定义 `CommandDefinition`：类型（Follow/AttackMove/Defend/Hold/Retreat/Rally）、范围/速度/持续等参数。
- 词条/遗物 `ArtifactDefinition`：名称、稀有度（铜/银/金/传说）、效果脚本 Id、叠加规则。
- 事件 `EncounterDefinition`：条件、选项、奖励/代价、触发时机（战斗中/波次间/结算）。
- 波次 `WaveDefinition`：时间轴/批次、敌人类型与数量、出怪口方向、提示时间、是否“流量刺”。
- 数据放置：`Assets/_Game/ScriptableObjects/...`，运行时经 `CY.Resource` 加载；高频数据可预加载缓存。

## 6. 单位系统实现要点
- 注册实体：在启动时 `CY.Entity.RegisterEntity` 注册员工、敌人、Boss 三类实体，挂载对应组件（表现+逻辑）。
- 生成/回收：战斗流程中用 `CY.Entity.ShowEntity<T>()` 创建；死亡/自闭时 `HideEntity` 回收。
- AI 等级与职业能力：按策划表 Lv1-Lv5，技能/被动写成可配置行为（避免硬编码魔法数）。
- 资源掉落：死亡触发事件，生成资源拾取物；Boss/员工拾取时更新 `ResourceState` 并广播事件。
- 状态：自闭/受伤/死亡/复活，状态机驱动动画与 AI；Boss 自闭需资源或时间恢复。

## 7. 指挥系统（Boss 指令）
- 指令输入：UI 或快捷键（F/A/D/S/R/G）。UI 触发事件发给战斗系统。
- 范围校验：Boss 指令仅对范围内员工有效（依策划指挥半径）；超出则无效或提示。
- 行为：
  - Follow：跟随 Boss。
  - AttackMove：向目标点移动并攻击沿途敌人。
  - Defend：原地防御，减伤、不可移动（可配置三档：原地/拦截/智能防御）。
  - Hold：驻留当前位置，禁止移动，继续攻击。
  - Retreat：向后撤到安全点。
  - Rally：集合到 Boss 位置。
- 指令栈与覆盖：同一单位仅保留一个当前指令；新指令覆盖旧指令，旧指令完成/撤销时回调事件。

## 8. 战斗循环与波次
- 启动战斗：加载波次配置，初始化计时器；播放预警阶段（如 10s）。
- 波次调度：计时触发生成敌人；支持“流量刺”随机插入。
- 战斗结果：敌方全灭或守点成功 -> 结算胜利；Boss/核心点被摧毁 -> 失败；广播事件进入结算流程。
- 资源：Gold/Corruption/Conscience 三类，掉落、拾取、消耗路径明确（招募/升级/技能/事件）。
- 计时器：用 `CY.Timer.Delay/Loop`，避免 `Update` 手写计时。

## 9. UI 实现细则
- 目录：`Assets/_Game/Scripts/UI`；UI Prefab 放 `Assets/_Game/Prefabs/UI/...`，路径通过 `[UIPrefab("UI/Menu/Main/MainUI")]` 等指定。
- 面板打开/关闭：`CY.UI.Open<T>() / CY.UI.Close<T>()`，不要 `Destroy(this)`。
- 对象池：关闭回收到 `[ObjectPools]/UI`，复用时恢复 sibling index，层级顺序不乱。
- HUD 高频数据：使用 Typed MVVM；关闭时 Dispose 订阅。
- 典型界面：
  - 主界面/加载界面（已有）：按钮进入战斗流程。
  - 战斗 HUD：资源数值、指令按钮、快捷键提示、波次/倒计时、Boss 状态、自闭提示。
  - 结算：展示奖励/代价，进入 Meta 或返回菜单。
  - Roguelike 事件弹窗：选项按钮、效果预览。

## 10. 随机事件与 Roguelike
- 事件库：依据策划 10+ 事件，数据化为 `EncounterDefinition`，含条件、选项、奖励/代价、出现权重。
- 触发时机：战斗间隔、波次间、结算前、关卡特殊点。
- 执行：事件系统广播事件 -> UI 弹窗 -> 玩家选择 -> 结果写回资源/单位/遗物。
- 办公用品/遗物：按稀有度掉落，效果脚本 Id 映射到具体逻辑（Buff、资源变换、指令变化等）。

## 11. Meta 经营与存档
- 资源：Reputation（声望）用于装修升级；升级效果写入全局被动（HP/攻速/指挥范围等）。
- 存档：用 `CY.SaveData/CY.LoadData`；结构含装修等级、解锁单位/部门、全局被动、上次事件状态等。
- 入口：在主界面加载存档，战斗/结算更新存档。

## 12. 美术与音频
- 美术风格：参考 `资源/策划/美术风格指南.md`，保持“办公+塔防”风格，UI 色彩与字体一致。
- 音效：按钮/指令/掉落/战斗/Boss 自闭/复活；可放 `Assets/_Game/Resources/Audio`。
- 动效：面板淡入淡出使用 UIManager 默认动画；高频粒子/特效避免 GC。

## 13. 性能与平台约束
- WebGL/微信：不可依赖 AppDomain 扫描；流程注册表必须生成；避免多线程 Job。
- GC：Update/FixedUpdate 避免 LINQ/闭包/new 列表/字符串拼接；复用缓存。
- 订阅生命周期：UI/实体销毁或关闭时 `UnsubscribeAll(this)`，避免事件泄漏。

## 14. 测试与验收
- 功能自测：启动→主界面→战斗→结算回归；指令行为与策划一致；资源收支正确；UI 关闭无残留。
- 数据回归：波次/职业/事件配置修改后跑冒烟；持久化读写无异常。
- 平台检查：WebGL/微信目标下运行，流程注册表可用，资源路径正确。

## 15. 开发步骤速查（你可以按此逐项执行）
1) 生成/更新流程注册表（改动流程后必做）。  
2) 创建/补全 ScriptableObject：单位、部门、指令、波次、事件、遗物。  
3) 战斗流程：初始化数据、加载波次、生成敌/我方实体。  
4) 指挥系统：监听 UI/快捷键事件，分发到单位 AI，落实 F/A/D/S/R/G。  
5) 资源系统：拾取/掉落/消耗，UI 实时刷新。  
6) 随机事件：读取事件表，触发弹窗，执行选项。  
7) 结算与 Meta：结算奖励、声望升级、存档。  
8) 打磨：UI/动效/音效、性能、平台适配。
